# 클래스 채팅방 UI/기능 점검 메모

## 목적
`https://b-square-web.pages.dev/community/community?room=cls_89494c0bf9254d1e&type=class` 화면을 기준으로, 이후 실제 개선 작업을 지시할 때 바로 사용할 수 있는 문제 목록과 작업 방향을 정리한 문서다.

## 검토 범위
- 배포 화면 렌더링 확인: `qa-shots/community-class-chat.png`
- 주요 구현 파일: `community/community.html`, `community/community_v2.js`, `community/chat_ui.js`, `community/chat_list_v2.js`, `community/sync_bridge.js`, `community/dm_private.js`
- 스타일 파일: `community/community_refined.css`, `community/community_mobile_app.css`
- 첫 진입 가이드 모달 관련 파일: `kakao_quick.js`

## 참고 메모
- 실제 배포 화면은 첫 진입 시 가이드 모달이 메인 UI를 크게 덮고 있어서, 화면 확인은 스크린샷과 코드 분석을 함께 기준으로 삼았다.
- 아래 항목은 “바로 고쳐야 하는 것”과 “사용성/완성도 측면에서 꼭 보완해야 하는 것”을 섞지 않고 분리했다.

## 1. 즉시 수정 필요

### [P0] 모집 카드 생성 모달이 실제로 동작하지 않음
- 현상: 모집 카드 모달의 버튼/입력 필드 id가 HTML과 JS에서 서로 다르다.
- 영향: 클래스 채팅에서 모집 카드 생성, 닫기, 제출 흐름이 사실상 깨져 있다.
- 작업 방향: `setupGatheringUI()`가 찾는 id와 `community.html`의 실제 id를 하나로 맞춰야 한다. 설명 필드가 필요하면 HTML에 추가하고, 필요 없으면 JS 참조를 제거해야 한다.
- 참고 파일: `community/chat_ui.js`, `community/community.html`

### [P1] “새 대화 시작”이 실제 DM 시작 흐름으로 이어지지 않음
- 현상: 새 대화 모달에서 사용자를 선택해도 직접 DM을 여는 대신 `window.addFriend()` 흐름으로 빠진다.
- 영향: 사용자는 “대화 시작”을 기대했는데 친구 요청 또는 프로필 팝업으로 이동할 수 있어 목적과 결과가 어긋난다.
- 작업 방향: 새 대화 모달에서는 `openDirectChat()`로 바로 연결하고, 친구 추가/프로필 보기 동선은 별도 버튼으로 분리하는 편이 좋다.
- 참고 파일: `community/community_v2.js`

### [P1] 그룹 채팅 생성 후 생성된 방으로 자동 진입하지 않음
- 현상: 그룹 생성 성공 후 목록만 다시 로드하고 끝난다.
- 영향: 사용자가 방을 다시 목록에서 찾아 눌러야 해서 흐름이 끊긴다.
- 작업 방향: 생성 응답에서 방 id를 받아 곧바로 `ChatUI.openRoom()`, `ChatList.setActiveRoom()`, `updateRoomQuery()`까지 이어주는 것이 자연스럽다.
- 참고 파일: `community/community_v2.js`

### [P1] 읽음 처리 상태가 세션 간 일관되게 유지되지 않을 가능성이 큼
- 현상: `markAsRead()`가 로컬 상태와 이벤트 emit 수준에 머무르고, 서버 저장 동작이 보이지 않는다.
- 영향: 새로고침, 다중 탭, 다른 기기에서 unread 배지가 다시 살아날 수 있다.
- 작업 방향: 읽음 시점을 서버에 저장하는 API를 붙이거나, 적어도 unread 계산 소스를 한 군데로 통일해야 한다.
- 참고 파일: `community/sync_bridge.js`, `community/chat_list_v2.js`

### [P1] 고정 메시지 조회 파라미터 규격이 파일마다 다름
- 현상: 클래스 채팅 쿼리에서는 `pinned_only=true`, 다른 곳에서는 `pinned_only=1`을 사용한다.
- 영향: 백엔드 구현에 따라 고정 메시지 바나 정보 패널이 불안정하게 동작할 수 있다.
- 작업 방향: `pinned_only` 파라미터를 하나의 규격으로 통일하고, 백엔드와 프런트 모두 같은 규칙을 따르게 해야 한다.
- 참고 파일: `community/chat_ui.js`, `community/sync_bridge.js`

### [P2] DM 보조 모듈에 미구현 함수가 남아 있음
- 현상: `dm_private.js`의 편집/삭제/리액션 함수가 `not implemented` 상태다.
- 영향: 추후 해당 모듈을 직접 타는 경로가 생기면 메시지 조작 기능이 작동하지 않는다.
- 작업 방향: 현재 `ChatUI` 기준으로 API를 붙여 완성하거나, 사용되지 않는 경로라면 노출을 줄여 혼선을 막아야 한다.
- 참고 파일: `community/dm_private.js`

## 2. UI/레이아웃/사용성 보완

### [P1] 모바일 기준이 `768px`과 `1024px`로 나뉘어 레이아웃이 어색해짐
- 현상: `setMobileViewMode()`는 `1024px` 이하를 모바일처럼 다루는데, 모바일 전용 chrome/FAB/칩은 `768px` 이하에서만 붙는다.
- 영향: 769~1024 구간에서 사이드바는 접히는데 모바일 보조 UI는 안 붙는 반쪽 상태가 생길 수 있다.
- 작업 방향: 브레이크포인트를 하나로 통일하거나, 태블릿 전용 레이아웃을 별도로 정의해야 한다.
- 참고 파일: `community/chat_ui.js`, `community/community_v2.js`, `community/community_refined.css`, `community/community_mobile_app.css`

### [P1] 모바일에서 클래스 채팅의 핵심 동선인 “클래스 상세로 이동”이 사라짐
- 현상: 클래스 방 헤더에서는 `btnGoToClass`를 노출하지만 모바일 CSS에서 강제로 숨긴다.
- 영향: 사용자가 “지금 어떤 클래스의 채팅인지”, “클래스 상세로 어떻게 돌아가는지”를 잃기 쉽다.
- 작업 방향: 모바일에서도 아이콘형 축약 버튼이나 오버플로우 메뉴 형태로 유지하는 것이 좋다.
- 참고 파일: `community/chat_ui.js`, `community/community.html`, `community/community_mobile_app.css`

### [P1] 모바일 하단 액션이 서로 충돌함
- 현상: sticky 입력창, 스크롤 하단 이동 버튼, 새 대화 FAB가 모두 하단 우측/하단 영역을 경쟁한다.
- 영향: 입력과 전송에 집중해야 하는 채팅 화면에서 시야 분산과 터치 충돌이 생긴다.
- 작업 방향: 채팅방 진입 시 FAB는 숨기고, 스크롤 버튼은 입력창과 겹치지 않게 위치/동작을 재설계해야 한다.
- 참고 파일: `community/chat_ui.js`, `community/community_v2.js`, `community/community_mobile_app.css`

### [P1] 정보 패널이 모바일에서 드로어처럼 열리지만 모달 UX가 부족함
- 현상: 모바일에서 정보 패널은 사실상 오버레이 성격인데 포커스 트랩, ESC 닫기, 배경 비활성화 같은 처리가 약하다.
- 영향: 정보 확인 후 다시 채팅으로 복귀하는 흐름이 매끄럽지 않고, 접근성도 떨어진다.
- 작업 방향: 모바일에서는 별도 바텀시트/드로어 컴포넌트로 재정의하거나, 최소한 모달 수준의 상호작용 규칙을 맞춰야 한다.
- 참고 파일: `community/chat_ui.js`, `community/community_refined.css`, `community/community_mobile_app.css`

### [P1] 첫 진입 가이드 모달이 메인 채팅 UI를 과하게 가림
- 현상: 데스크톱 첫 방문 시 `환영합니다` 가이드 모달이 떠서 채팅 화면을 상당 부분 가린다.
- 영향: 사용자는 실제 채팅 UI를 보기 전에 안내 레이어부터 닫아야 하고, 첫인상에서 핵심 기능보다 방해 요소가 먼저 보인다.
- 작업 방향: 커뮤니티/채팅 화면에서는 가이드 모달을 더 작게 줄이거나, 도움말 아이콘/툴팁 방식으로 낮추는 것이 좋다.
- 참고 파일: `kakao_quick.js`, `qa-shots/community-class-chat.png`

### [P1] 채팅방 목록 아이템이 키보드 접근성을 거의 지원하지 않음
- 현상: `.chat-room-item`이 클릭 가능한 `div` 중심으로 구현되어 있고, 키보드 포커스/Enter/Space 동작이 없다.
- 영향: 키보드 사용자와 스크린리더 사용자에게 채팅방 진입이 어려워진다.
- 작업 방향: `button` 또는 `a` 기반으로 바꾸거나, `role`, `tabindex`, 키다운 핸들러, 포커스 스타일을 보강해야 한다.
- 참고 파일: `community/chat_list_v2.js`, `community/community_refined.css`

### [P2] 모바일에서 사용자 테마 선택을 무시하고 라이트 테마를 강제함
- 현상: 모바일 셸 초기화 시 `data-theme = 'light'`를 직접 주입한다.
- 영향: 다크 테마 사용자가 갑자기 다른 시각 언어를 보게 되고, 설정 일관성이 깨진다.
- 작업 방향: 사용자 테마를 유지하되 모바일 가독성만 별도로 조정해야 한다.
- 참고 파일: `community/community_v2.js`

### [P2] 메시지 검색이 현재 DOM에 렌더된 메시지만 찾음
- 현상: 오래된 히스토리를 서버에서 다시 찾는 구조가 아니라 현재 화면에 올라온 메시지만 검색한다.
- 영향: 사용자는 “검색이 안 된다”고 느끼기 쉽고, 긴 대화방일수록 검색 가치가 떨어진다.
- 작업 방향: 서버 검색 또는 히스토리 로드와 결합된 검색으로 확장하고, 결과 내 이전/다음 이동도 넣는 것이 좋다.
- 참고 파일: `community/chat_ui.js`

### [P2] 검색 결과 탐색 UX가 약함
- 현상: 결과 수 표시는 있지만 결과 간 이동, 현재 위치 표시, ESC 종료 같은 기본 동작이 빈약하다.
- 영향: 검색은 되더라도 “지금 몇 번째 결과인지”, “다음 결과가 어디인지”를 알기 어렵다.
- 작업 방향: 결과 카운트, 이전/다음 버튼, 검색 상태 고정 영역을 추가하는 편이 좋다.
- 참고 파일: `community/chat_ui.js`, `community/chat_list_v2.js`

### [P2] 그룹 정보 패널이 너무 얇음
- 현상: 현재 그룹 정보 패널은 그룹명과 아이콘 정도만 보여준다.
- 영향: 멤버 목록, 초대, 방 나가기, 알림 설정 등 실제로 필요한 관리 기능이 없다.
- 작업 방향: 클래스 정보 패널 수준까지는 아니더라도, 그룹 멤버/참여자 수/초대/나가기/알림 토글 정도는 제공해야 한다.
- 참고 파일: `community/chat_ui.js`

### [P2] 폴더/대화 관리 동선이 `prompt`, `confirm`, 컨텍스트 메뉴에 치우쳐 있음
- 현상: 폴더 지정, 대화 삭제 같은 기능이 숨은 우클릭 메뉴와 기본 브라우저 다이얼로그에 의존한다.
- 영향: 모바일에서는 발견성이 낮고, 전체 UI 톤과도 어울리지 않는다.
- 작업 방향: 정보 패널 또는 명시적인 액션 메뉴에서 동일한 기능을 제공하는 편이 좋다.
- 참고 파일: `community/chat_list_v2.js`

## 3. 추가되면 좋은 기능

### [Nice to have] 메시지 전송 실패 상태와 재시도 액션
- 현재는 실패 시 조용히 사라지거나 토스트 수준으로 끝나는 흐름이 있어 보인다.
- 실패 배지, 재전송 버튼, 임시 저장 상태가 있으면 채팅 안정감이 훨씬 좋아진다.

### [Nice to have] 읽지 않은 메시지 구분선
- “여기까지 읽음” 또는 “새 메시지” 구분선이 있으면 방 재진입 시 맥락 파악이 쉬워진다.

### [Nice to have] 방별 알림 설정의 명시적 노출
- 지금도 mute 개념은 있지만 발견성이 낮다.
- 헤더나 정보 패널에서 알림 켜기/끄기, 고정, 방 이동 기능을 명시적으로 노출하면 좋다.

### [Nice to have] 첨부 파일 업로드 진행률/용량 안내
- 이미지/파일 전송은 optimistic UI가 있지만 진행률과 실패 사유 안내가 부족하다.
- 큰 파일 전송 시 사용자 신뢰도가 떨어질 수 있다.

### [Nice to have] 클래스 채팅에 맞는 컨텍스트 기능
- 공지 고정, 과제/일정 바로가기, 출석/모임 관련 빠른 액션 등 클래스 채팅다운 기능을 붙일 여지가 크다.

## 4. 추천 작업 순서

### 1차
- 모집 카드 모달 id 불일치 수정
- 새 대화 시작을 실제 DM 열기 흐름으로 수정
- 그룹 채팅 생성 후 자동 입장 연결
- 읽음 처리/고정 메시지 파라미터 규격 정리

### 2차
- 모바일 브레이크포인트 통일
- 모바일 하단 액션 충돌 정리
- 모바일에서 클래스 상세 이동 동선 복구
- 정보 패널 모바일 UX 개선

### 3차
- 검색 UX 확장
- 그룹 정보 패널 고도화
- 폴더/관리 액션 UI 재설계
- 테마 강제 로직 제거

### 4차
- 실패 재시도, 읽지 않은 메시지 구분선, 업로드 진행률 같은 완성도 기능 추가

## 한 줄 결론
현재 클래스 채팅방은 “기본 골격은 괜찮지만, 실제 사용 흐름을 끊는 기능 버그와 모바일 UX 불일치가 남아 있는 상태”다. 다음 작업은 디자인 손보기보다 먼저, 모집 카드/새 대화/읽음 처리/모바일 기준 통일부터 들어가는 것이 맞다.
